## 第二轮：130 分钟真实回放（2026-11-16 下午）

用一场完整回放（1561 句 / 42306 字）反查，方法：

1. 统计候选词频次（`白省 11 / 云雅 33 / 白六 20 / 培文 14 ...`）
2. 按校名命名模式定向挖掘（`X中/X附/X实/X雅`）
3. **逐条看上下文确认**，不确认的不入库

### 新增纠错（A 级：有原文对照）

| 错写法 | 正确 | 依据 |
|---|---|---|
| `白神南山` | `白省南山` | "黄埔军校跟**白神**南山" → 白省南山班 |
| `白神` | `白省` | 同上，3 处 |
| `历城南山` | `荔省南山` | "**历城南**山跟云阳的冠冕" |
| `云阳` | `云雅` | "**云阳**跟高一的高8分" → 同句讲云雅冠名 |
| `云阳的冠冕` | `云雅冠名` | 冠冕=冠名，同音 |

### 明确剔除（证据不足，宁缺勿滥）

| 候选 | 剔除原因 |
|---|---|
| `青华` | 仅 1 处，上下文是"青华中哪一个"，无法确定是清华还是某校简称 |
| `小云中` | 看上下文是**主播账号名**（"把小云中招搜一下"），不是学校 |
| `白绿克兰` | 谐音无法还原，强行收录会误导 |
| `静雅` | "静雅为什么这么多静校" — 疑似"精华/进华"之类，证据不足 |

**这一轮的教训**：词表能力越大，误伤风险越大。不确定的一律不收。

## 第三轮：修复词表自身的三个 bug（同日）

用真实转录跑完整流程时暴露出来的，都是**代码问题**，不是数据问题。

### 1. 数字被误改

`百六 → 白六` 这条规则把「一百六十个人」改成了「一白六十个人」。

修法：替换前检查替换词首尾字符与相邻字符，若构成数字串则跳过。

**踩到的 Python 陷阱**：`"" in "0123456789"` 返回 `True`（空串是任何字符串的子串），
导致句首/句尾的词永远被判定为"紧邻数字"而永不替换。必须显式判空。

### 2. 暗语展开出现嵌套括号

`清实 → 清远实验（清实）`，二次扫描把括号里的又展开一遍：
`清实（清远实验（清实））`

修法：从「逐词全局 replace」改为「单次从左到右扫描，最左最长优先」。

### 3. 长短词冲突

`小金 → 金广附` 先命中，破坏 `小金龙`：`小金（金广附）龙（金广附）`

修法：同上，最长优先 + 替换后跳过整段。

### 4. 展开不幂等

已展开的 `小金龙（金广附）` 再次处理会变成 `小金龙（金广附）（金广附）`。

修法：检测源文本是否已是 `code（正式名）` 形式，是则原样跳过。

## 后续怎么加

每场直播后跑一次：

```bash
python -m wxlive transcribe output/recordings/xxx.wav
```

然后检查产出 md 里读起来别扭的地方，补进 `lexicon/xsc.json` 的 `corrections`。

**判断标准**：有上下文能确认的才加。加错一条比漏掉十条更糟——
错的规则会在每份转录里重复犯错。
