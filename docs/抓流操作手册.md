# 视频号直播流地址获取：实操手册

> 验证时间：2026-11-16 12:00–12:20
> 工具版本：wx_channels_download v261106（2026-11-06 发布）
> 本机环境：Windows / 微信 4.1.1.19 / 系统代理固定 `127.0.0.1:10808`

---

## 一、先说结论：改 UA 这条路走不通

网上流传的"F12 把 Chrome 伪装成手机 UA 就能看视频号"，**对直播取流无效**。实测证据：

### 1. 环境检测不只看 UA

视频号网页端 bundle（`816.c7a59812.js`）的真实判断逻辑：

```js
eQ = () => {
  let ua = navigator.userAgent;
  return ua.includes("MicroMessenger") &&
         (ua.includes("WindowsWechat") || ua.includes("MacWechat"))
}
```

要求 UA 里**同时**有 `MicroMessenger` 和 `WindowsWechat`。后者是 PC 微信专用标记，
普通 Chrome 无论怎么改 UA 都只在模拟，且这个分支本身就是给"微信内置浏览器"用的。

### 2. 就算 UA 骗过了，也拿不到数据

页面真正取流靠的是微信客户端注入的原生桥：

- `window.WeixinPrefecherJSBridge.invoke`（函数指针）
- `wxNative.webTransfer`
- `wx.request`

这些只有微信自己的 WebView 里才存在。Chrome 里它们是 `undefined`。

### 3. 实测未登录调接口：直接拒绝

我拿"PC 微信 UA"直接 POST 真接口：

```
POST https://channels.weixin.qq.com/cgi-bin/mmfinderassistant-bin/live/join_live
→ {"errCode":300330,"errMsg":"request failed"}
```

`300330` 在其错误码表中定义为 **`MinNeedLogin`** —— 服务端还要 sessionid + 登录态，
请求头伪造过不去。

**一句话：UA 伪装能骗页面，骗不过接口。**

## 二、正确做法：本地 MITM 代理 + 注入

### 2.1 为什么这个方案能成

`join_live` 接口的响应里带 `liveSdkInfo.liveCdnUrl` —— 这就是带签名（`txTime` + `txSecret`）
的可直录 FLV 地址。问题只在于：**这个响应只有微信客户端能拿到**。

MITM 代理的思路：把自己插在微信和腾讯服务器之间，解密 HTTPS，
往页面里注入钩子脚本，等播放器自己拿到地址时顺手把它截下来。

### 2.2 工具已就位

```
D:\File\01_Vibe_Coding\14-WeChat_live\tools\wxcd\
  wx_video_download.exe     # v261106
  config.yaml               # 已按本机环境改好
  config.yaml.orig          # 原始备份
```

已做的两处适配：

| 配置项 | 值 | 原因 |
|---|---|---|
| `proxy.upstreamProxy` | `http://127.0.0.1:10808` | **关键**：本机 10808 是固定出口。不接这条，工具接管代理后 Telegram/Alma 全断 |
| `download.dir` | `<项目>/output/recordings` | 录下来的文件直接落在项目里 |

### 2.3 启动方式（有个大坑）

**必须用根命令启动，不能用 `server` 子命令。**

`cmd/server.go:78` 里硬编码了：

```go
func apply_server_config_defaults() {
    Cfg.Update("proxy.skipInstallRootCert", true)
    Cfg.Update("proxy.enabled", false)   // ← 强制关掉代理
    Cfg.Update("proxy.system", false)
}
```

用 `wx_video_download.exe server` 启动，代理永远起不来，而且不报错，
只会静默只启动 API（2022）。我在这上面耗了不少时间。

**正确启动：**

```bash
cd /d/File/01_Vibe_Coding/14-WeChat_live/tools/wxcd
./wx_video_download.exe            # 根命令，不要加 server
```

成功标志（三个都要有）：

```
Proxy service started successfully, address: http://127.0.0.1:2023
API service started successfully, address: http://127.0.0.1:2022
```

验证：

```bash
netstat -ano | grep -E ":202[0-9]"          # 2022 和 2023 都在 LISTENING
curl -s http://127.0.0.1:2022/api/status     # proxy.listening 要为 true
```

### 2.4 取流步骤

1. 启动上面的工具（保持窗口不关）
2. **打开微信 PC 端** → 进入目标直播
3. 直播页的"更多"按钮（或侧边/底部浮动按钮）会多出一个**下载图标**
4. 点它 → 下拉菜单里有多个清晰度选项，点任意一个 → **自动复制一条 ffmpeg 命令**到剪贴板

复制出来的大概是：

```bash
ffmpeg -i "https://finder.video.qq.com/...flv?txTime=...&txSecret=..." -c copy -y "live_xxx.flv"
```

### 2.5 接到我们的 pipeline

把 URL 抠出来，喂给已有的 `stream` 子命令：

```bash
.venv-trim/Scripts/python.exe -m wxlive stream "<粘贴的URL>" --name 直播名
```

这个子命令已经实现的能力（`wxlive/stream_capture.py`）：

- ffprobe 先探音轨，避免录几小时发现没声
- 直接输出 16k 单声道 WAV（省一半磁盘 + 省重采样）
- `-vn` 丢视频轨，CPU 几乎为零
- 断流自动重连（`-reconnect 1`，最多 10 秒间隔）
- 90 秒无新数据判流，连续 3 次停止并提示地址过期

## 三、踩过的坑（都已解决）

### 坑 1：`server` 子命令强制关代理
见 2.3。源码硬编码，改配置无效。

### 坑 2：配好的 `proxy.enabled: true` 变成了 false
第一次启动用了 `server`，它把 false **写回了 config.yaml**。
所以要先停掉、改回 true、再用根命令启动。

### 坑 3：残留 PID 文件导致"服务器已在运行"
异常退出（比如被 timeout 杀掉）会留下 `wx_video_download.pid`，
里面记着一个已经不存在的 PID，导致下次启动直接报错退出。

```bash
# 现象
Failed to run: 服务器已在运行, PID: 43264
# 但 43264 根本不存在
```

处理：`rm -f wx_video_download.pid` 后重试。

### 坑 4：担心搞坏系统代理
启动前备份过：`1|127.0.0.1:10808`。

实际验证：只要 `proxy.system` 保持 `false`，工具**不会**改系统代理。
全程系统代理一直是 10808，录音和 Telegram 都没断。

如果哪天被改坏了，恢复：

```powershell
Set-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' -Name ProxyEnable -Value 1
Set-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' -Name ProxyServer -Value '127.0.0.1:10808'
```

### 坑 5：curl 直连 2023 返回 000
这是正常的 —— 它是 MITM 代理，证书是自签的。curl 不信任就断。
加 `-k` 就正常了（实测返回 200，页面 1.16MB，注入标齐全）。

浏览器/微信里没这个问题，因为工具会自动把根证书装进系统信任区
（`proxy.skipInstallRootCert: false` 时必须，需要管理员权限）。

## 五、什么时候用哪条路

| 场景 | 推荐 |
|---|---|
| 临时录一场，人在电脑前 | **声卡回环**（零配置，已跑通） |
| 长时间挂机 / 追求音质 / 不想让微信占音频设备 | **流地址直录** |
| 手机端直播、电脑上不方便开微信 | 只能声卡回环（或手机投屏） |

流地址直录的真正优势不是"能录"，而是：

- 音质是**数字原流**，不是声卡重采样后的
- CPU 占用极低（`-vn` 丢视频后几乎没有负载）
- 不独占音频设备，能同时干别的
- 不受微信音量、静音、虚拟声卡干扰

## 六、风险提示

- 这个工具会**接管系统代理**，本质是中间人。腾讯如果做证书固定（pinning），这条路会失效
- 微信版本更新可能改变注入点，届时需要跟进工具更新
- 仅用于个人学习研究，注意合规边界
- 工具会安装根证书到系统信任区，用完想清干净可以跑 `wx_video_download.exe uninstall`
