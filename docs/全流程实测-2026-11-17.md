## 二、暴露的真缺陷：收尾阶段可能跑不完（P0）

### 现象

第一次跑（10 分钟设定）：

- 音频：**592s（9.9 分钟）**，完整
- 转写：**只到 404.9s**，**差 187 秒（3.1 分钟）**
- `json` 文件**根本没生成** → `session.close()` 没执行
- 进程退出码 1，恰好 600s 时被外部超时终止

### 根因（已定位，非推测）

日志里的关键证据：

```
[status] 已录 6.0min ... 队列 1 [gemini-asr] 24.9s 音频 → 11 句, 耗时 80.4s (RTF=3.23)
[status] 已录 8.0min ... 队列 5 [gemini-asr] 19.9s 音频 → 4 句, 耗时 74.8s (RTF=3.77)
[status] 已录 9.5min ... 队列 9
```

**网关在这两个片段的 RTF 从 0.35 飙到 3.2–3.8**（慢了约 10 倍）。
队列从 0 一路堆到 9。到 `max_seconds=600` 触发停止时，队列里还有 3 分钟音频没转。

收尾逻辑本身是对的（`_enqueue_tail` 会把剩余喂进队列，然后
`join(timeout=600)` 等 ASR 排空）——**但它需要额外时间，而录制时长一到，
调用方/外部就认为"该结束了"**。

### 这暴露的设计问题（比这次超时更重要）

1. **`max_seconds` 只管录制时长，不管收尾时长。**
   用户设"录 10 分钟"，实际进程会在 10 分钟 + 收尾时间才退出。
   任何按录制时长设超时的外部调度（cron、shell timeout、GUI 的等待）都会截断它。
2. **`join(timeout=600)` 超时后无提示。**
   如果 600s 内没转完，`_asr_thread` 仍在跑，但 `session.close()` 照常执行
   → 产出的 json 会**缺少尾部句子，而使用者完全看不出来**。
   这与 P0-2（静默丢数据）是同一类问题，只是发生在更外层。
3. **ASR 慢下来时没有背压提示。**
   队列从 0 堆到 9 的过程中，日志只有数字变化，没有"转写落后于录制"的告警。

### 影响面（重要）

- **短录制（≤30 分钟）一般没事**：RTF 0.35，转写速度是录制的 3 倍。
- **长录制 + 网关抖动就会踩**：2.4 小时直播若中途出现几次 RTF 3+，
  累计可能落后几分钟。今天早上那场 86 分钟能跑完，是因为没遇到持续抖动。

### 建议修法（未实施，待决策）

1. `run()` 增加 `drain_timeout` 概念：录制结束后**明确告知预计还需多久**，
   并在日志里打印"录制已完成，正在转写剩余 N 个片段"。
2. `join()` 超时后**必须报警**，而不是静默继续 close：
   把未转完的片段音频落到 `output/spilled/`（复用已有 `_spill_audio`），
   并在 meta 里记 `incomplete: true` + 未转区间。
3. 队列堆积超过阈值（如 >5）时打 warn，提示"转写落后，可能是网关变慢"。

## 三、顺带确认的两件事

### 1. 直播结束后会把其他声音录进来（不是 bug，但要知道）

405s 之后补转出来的内容是：

```
那今天就到这了，我们明天节目当中见，各位拜拜。
Why should I? / Yes, surface dweller. / By Azshara! / Death to the surface!
```

前一句是直播收尾，后面是**游戏音效**。因为 loopback 录的是"系统正在播放的声音"，
直播结束后切到游戏，游戏声音就进来了。

**这不是缺陷**，但说明：静音自动停止（40s）在有其他声音时不会触发。
如果要自动截断，需要别的判断依据（例如标题/进程监听）。

### 2. 词表与内容不匹配时纠错量会很小

这次是财经直播，词表是升学（170 校名），纠错只改 7 处。
**这是正确行为**（不该硬套词表），也说明纠错确实是"只改明显听错的"而非乱改。

## 四、结论

**核心链路（16k 录制 / 重采样 / VAD / ASR / 纠错 / 要点 / 产物分离 / meta）全部实测通过。**

**新发现 1 个 P0 级缺陷**：录制时长到点后，收尾转写可能被外部超时截断，
且截断时无任何提示，产物看起来"正常"但少了尾部内容。

这条比之前修的两个 P0 更隐蔽：前两个有明确报错可查，
这个表现为"产物正常但内容不全"，只有对比音频时长才能发现。
