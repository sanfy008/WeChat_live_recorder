# 采集操作指南：直播 / 回放怎么保证录全

> 最后更新：2026-11-16
> 针对本机环境：Windows + 微信 4.1.1.19 + 抓流工具（tools/wxcd）

---

## 一、先分清三种场景

这是最关键的一步。**不同场景用不同方法，用错了会漏内容。**

| 场景 | 特征 | 该用什么 | 为什么 |
|---|---|---|---|
| **A. 正在直播（实时）** | 主播正在讲，进度条在涨 | **声卡回环录制** | 直播流没有"从头"的概念，中途接入只能录到接入之后；回环最稳 |
| **B. 已结束的回放** | 有完整进度条（如 `4:00 / 81:16`） | **抓流下载** | 能拿到完整文件，音质是数字原流 |
| **C. 刚从直播转回放** | 直播结束，视频号生成了回放 | **等回放生成 → 抓流下载** | 不用守全程，事后一次性拿全 |

**核心判断**：看有没有**完整可拖动的进度条**。
有 → 回放，走抓流；没有（LIVE 标记）→ 直播，走回环。

## 二、场景 B：回放（最简单，推荐）

### 操作步骤

1. **确认抓流工具在跑**

   ```bash
   cd /d/File/01_Vibe_Coding/14-WeChat_live/tools/wxcd
   ./wx_video_download.exe          # 注意：不要加 server 子命令！
   ```

   成功标志：
   ```
   Proxy service started successfully, address: http://127.0.0.1:2023
   API service started successfully, address: http://127.0.0.1:2022
   ```

2. **确认系统代理指向工具**

   ```bash
   powershell -Command "(Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings').ProxyServer"
   ```
   应该是 `127.0.0.1:2023`。如果是 `127.0.0.1:10808`，说明工具没接管，微信流量不会被拦截。

   开启方式：GUI 的「视频号下载」页签会提示；或调接口
   ```bash
   curl -X POST http://127.0.0.1:2022/api/proxy/system/enable
   ```

3. **在微信里打开回放，然后让它播几秒**

   ⚠️ **关键：必须让视频真的开始播放**。
   只打开页面不播放，请求不会发出去，工具就捕获不到。

4. **下载**

   - GUI：`启动.bat` → 「视频号下载」页签 → 刷新列表 → 选中 → 下载
   - CLI：`python -m wxlive fetch <标题关键词> --no-video`

5. **转写**（GUI 里勾"下载完自动转写"，或命令行加 `--transcribe`）

### 出问题怎么查

| 现象 | 原因 | 解法 |
|---|---|---|
| 列表是空的 | 视频没播放过 / 代理没开 | 播放几秒再刷新；检查 `proxy.system` |
| 提示"文件已加密但拿不到密钥" | 详情接口没返回 metadata | 重新在微信里打开一次（工具会重新捕获） |
| 下载到一半断了 | 地址过期 | 重新打开视频刷新地址，再下载 |
| `moov atom not found` | 解密长度不对（历史 bug，已修） | 升级到最新代码 |

## 三、场景 A：正在直播（最容易出错）

### 为什么直播不能用抓流下载

直播是**连续的实时流**，没有"完整文件"的概念。
你中途接入，就只能拿到接入之后的数据——**前面讲的都丢了**。

所以直播必须**从开头就守着录**。

### 正确操作

**方案 1：声卡回环录制（推荐）**

1. 直播开始前先打开微信，进入直播页
2. 启动录制：

   ```bash
   python -m wxlive record --name 某场直播
   ```
   或 GUI「录制」页 → 选回环 → 开始

3. **确认在录音**：状态栏显示已录时长、有音量条跳动
4. 直播结束后停止（或等静音自动停）

**注意**：回环录的是"电脑发出的声音"，所以：
- 微信音量不能静音（静音了就录不到）
- 不要同时播别的音频（会混进去）
- UU远程等虚拟声卡常驻没关系，但要确认选对设备

**方案 2：拿到直播流地址后 ffmpeg 直录（音质更好）**

工具能给出直播的 `liveCdnUrl`，用：

```bash
python -m wxlive stream "<直播流地址>" --name 某场直播
```

优点：数字原流、CPU 极低、不占音频设备。
缺点：需要先拿到地址（工具里有 `joinLive` 注入）。

**方案 3：手机端直播 → 电脑不方便时**

只能声卡回环 + 手机投屏，或者等回放。

### 直播的"完整性检查"

录完之后一定检查：

```bash
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 录音.wav
```

对比直播实际时长。如果明显短，说明中途掉过。

## 四、场景 C：直播转回放（最省力的思路）

**如果你不急着要实时文字**，这是最好的策略：

1. 直播开始后不用守着
2. 等直播结束，视频号会自动生成回放（通常几分钟到几小时）
3. 按「场景 B」抓流下载回放
4. 好处：完整、音质最好、还能倍速转写

**判断回放是否已生成**：在视频号里找到该主播主页，看最新内容里有没有带完整时长的视频。

## 五、几个"保证录全"的硬要点

### 1. 一定要检查结尾

转写完成后看 md 的最后几句：

```bash
tail -5 output/transcripts/xxx.md
```

正常情况下应该是主播的告别语，比如：

```
**[01:50:36]** 各位家长，那今天我们直播就到这里了。
**[01:50:40]** 好，感谢各位家长，拜拜。
```

**如果结尾是讲到一半戛然而止** → 录漏了，要补。
如果结尾是告别语 → 完整。

### 2. 时长要和预期对得上

| 来源 | 怎么核对 |
|---|---|
| 回放 | 下载时打印的"时长"要和微信里的进度条一致 |
| 直播 | 录音时长 ≈ 从开播到你停止的时间 |
| 转写后 | md 头部「时长」要和音频一致（注意：这里曾有个 bug，用墙钟差算导致偏小，已修） |

### 3. 抓流工具的三个常见坑

**坑 1：用了 `server` 子命令**
```bash
./wx_video_download.exe server   # ❌ 代理永远起不来，静默只启动 API
./wx_video_download.exe          # ✅ 根命令
```

**坑 2：`proxy.system = false`**
工具在跑但没接管系统代理，微信流量根本不经过它。检查：
```bash
curl -s http://127.0.0.1:2022/api/config | grep -o '"proxy.system[^,]*'
```

**坑 3：只打开页面不播放**
视频号是懒加载，不播放就不会请求媒体地址，工具捕获不到。

### 4. 用完记得还原代理

抓流工具接管系统代理（`127.0.0.1:2023`）是 MITM，长期开着不合适。

**关工具会自动还原**，但万一崩了手动改回：

```powershell
Set-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings' -Name ProxyServer -Value '127.0.0.1:10808'
```

## 七、日常最省事的组合

如果只是偶尔录几场：

1. **回放**：双击 `启动.bat` → 「视频号下载」页签 → 刷新 → 勾选 → 下载（勾上"自动转写"）→ 完事
2. **直播**：提前 5 分钟开 `record`，结束停止
3. 事后 `tail -5` 看一眼结尾确认完整

就这三步。
