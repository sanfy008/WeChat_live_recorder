# 输出格式优化：放弃秒级时间戳

> 实测时间：2026-11-16 17:25–17:40
> 结论：**秒级时间戳是伪精度，改成段落聚合后时间戳开销从 35.2% 降到 5.1%**

---

## 一、问题：秒级时间戳不可信

### 1.1 当前时间戳是估算的，不是测出来的

看 `gemini_asr.py:223`：

```python
# Gemini 不返回逐句时间戳，按字数比例估算分配
lens = [max(1, len(x)) for x in lines]
tot = sum(lens)
for line, ln in zip(lines, lens):
    span = dur * (ln / tot)     # ← 按字数硬摊
```

**一个 110 秒的块切成 24 句，每句的"时长"是按字数比例硬摊的。**
真人说话有停顿、语速有变化，所以：

- `[00:02:34]` 这种看着精确到秒的标记，**实际误差可达 ±10~30 秒**
- 想拿它回查原始音频的某个位置，基本对不上

### 1.2 成本：35.2% 的文本是时间戳

实测 81 分钟那条转录（863 句）：

| 项 | 数值 |
|---|---|
| 正文 | 23,850 字 |
| 时间戳开销 | 12,945 字 |
| **占比** | **35.2%** |
| 平均每句 | 28 字 |

给 LLM 做分析时，**超过三分之一的 token 花在不准确的秒数上**。

---

## 二、方案：语义聚合，只改 md

### 2.1 为什么不按固定时间切

试过固定 30 秒聚合，但直播有更强的结构信号——主播的转折话术：

```
"好，有家长问…"
"下一个问题…"
"来我们看一下…"
"那接下来…"
```

在这些地方断段，问答关系完整，比按秒切自然得多。

### 2.2 三层断段规则

`wxlive/render.py` 的 `group_segments()`：

| 规则 | 默认值 | 说明 |
|---|---|---|
| **语义转折** | 20 个转折话术 | 命中即断，优先级最高 |
| `min_seconds` | 8 秒 | 段落太短时先不断，避免一句一段的碎片 |
| `max_seconds` | 60 秒 | 长度兜底，防止长时间无转折时出现巨型段落 |
| `max_chars` | 400 字 | 字数兜底，防止长句堆砌 |

转折词只在**句首 12 字**内判断。句中出现（如"我刚才说了有家长问"）不算断点。

### 2.3 实测效果

81 分钟那条：

| 形式 | 段数 | 时间戳字符 | 占比 |
|---|---|---|---|
| 逐句 | 863 | 12,945 | **35.2%** |
| 段落聚合 | **92** | **1,310** | **5.1%** |

**条目数减少 89.3%，时间戳开销降到 5.1%。**

聚合后的效果：

```
**[01:26-02:24]** 好，有家长问预言实验的重点班怎么样？预言实验的重点班可能啊，
起码目前为止，预言实验其实是以前的镇龙中学，目前来说不是特别建议…
第二个问题，就是金广附和龙高选哪个，女孩子。…所以即使是女孩，我也是略建议金广附。

**[03:22-04:18]** 好，下一个问题，白六（白云六中）的强基跟金海岸的重点班哪个好…
```

**注意看**：`好，有家长问…`、`好，下一个问题…` 这些问答边界被完整保留，
比逐句版更容易理解上下文。

## 三、关键约束：零质量风险

### 3.1 ASR 层完全不动

这是最核心的设计原则。改动**只发生在输出渲染层**：

| 产物 | 格式 | 用途 |
|---|---|---|
| `.json` | 逐句 + 原始时间戳 | 精确回查、将来接说话人分离 |
| `.jsonl` | 逐句 | 崩溃安全恢复、断点续转 |
| `.md` | 段落聚合 | 人读、LLM 分析 |

**ASR 的识别过程一个字节都没变。** 所以不存在"文字转录质量下降"的风险。

### 3.2 有测试守着"一字不丢"

`tests/test_render.py` 里最关键的一条：

```python
def test_real_transcript_no_loss():
    """用真实转录验证：聚合后一字不丢。"""
    groups = render.group_segments(segs)
    joined = "".join(g["text"] for g in groups)
    original = "".join(s["text"] for s in segs)
    assert joined == original, "真实数据聚合后内容不一致"
```

18 个测试，覆盖：

- **内容零丢失**（拼接后逐字相等）
- 每句都落在段落里（`count` 之和 == 原句数）
- 空白/纯空格句正确处理
- 转折词触发断段
- `min_seconds` 防碎片
- `max_seconds` / `max_chars` 兜底生效
- 句中转折词**不**误触发
- 时间格式（超 1 小时用 `h:mm:ss`，不输出秒级小数）
- 段落时间单调且不重叠

### 3.3 顺手修掉一个真 bug

写测试时发现：原实现用 `if not text: continue` 判空，
但 `"   "`（纯空格）是 truthy，会把空白拼进正文 —— 实测出现过
`"有内容   "` 尾部带空格。

已修：先 `strip()` 再判空，并追加清理后的副本。

## 四、关于"按人员发言区分"

这是**最贴合内容本质**的方向，但有个硬前提：**得先知道谁在说话**（说话人分离）。

当前管线没有这个能力。加它的代价：

- 需要 diarization 模型（pyannote 之类）
- CPU 上慢，或要额外调云端
- **diarization 不准会误切，反而损害可读性**

所以这次**没有做**，而是用"语义转折"这个零成本的近似方案。
实测转折话术在直播间覆盖率不错，问答边界基本都能抓到。

将来要做 diarization，`.json` 的逐句结构已经准备好了。

---

## 五、遗留：Gemini 分句不稳定

多次跑同一段音频，句数会变（20/23/25/1）。

那个"1 句"不是丢内容——它把整段塞成一大段没分句，字数波动在 8% 以内。

**这个改动反而降低了它的影响**：既然 md 已经按语义聚合，
Gemini 分句粒度不一致就不再那么刺眼了。只是 `.json` 里的句级时间戳
仍然不准（本来就是估算的）。
