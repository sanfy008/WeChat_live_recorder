# 流地址直录：思路与取舍

调研时间：2026-11-16 · 触发问题：「能不能直接填直播地址，比录声卡更简单？」

---

## 一、两种方式的本质区别

| | 声卡回环（已有） | 流地址直录（新增） |
|---|---|---|
| 原理 | 录声卡输出端的声音 | 用 ffmpeg 从直播流取音轨 |
| 音质 | 经过声卡重编码 | **原始音轨，无损** |
| CPU/内存 | 极低 | **几乎为零**（`-vn` 丢视频） |
| 需要播放 | **必须**有声音在放 | 不需要，可静音录 |
| 受其他程序干扰 | 会（提示音、别的视频混进来） | 不会 |
| 无人值守 | 需保持播放 | 可长时间挂着 |
| **前提** | 无 | **必须先拿到流地址** |
| 地址过期 | 不涉及 | 会 403，需重新获取 |

**结论：URL 拉流更好，但卡在「拿地址」这一步。**

---

## 二、关键现实：微信不公开流地址

微信视频号的直播流地址（带签名的 FLV）不会出现在页面上，必须通过：

1. mitmproxy 作系统代理，解密 HTTPS
2. 改写 `channels.weixin.qq.com` 的 HTML，注入钩子
3. 替换 `WeixinJSBridge.invoke`，把播放器内部拿到的地址回传给本地

这是 [wxchannels-downloader](https://github.com/gui8912/wxchannels-downloader) 等项目的共同做法。
代价：装根证书、要管理员权限、每次微信改版可能要修。

**所以本项目的策略是：两条路都留着，各管各的场景。**

- 想省事 → 用声卡回环（零配置）
- 想音质最好/长时间挂着 → 先拿地址，再用流地址直录

## 四、已实现的能力

`wxlive/stream_capture.py`

```python
probe_url(url)          # 先探测：能不能拉、有没有音轨、什么格式
StreamRecorder(url)     # ffmpeg 拉流 → 直接输出 16k 单声道 WAV
```

命令行：
```bash
python -m wxlive stream "https://xxx.flv" --name 某场直播
```

GUI：「录制」页 → 选「流地址直录」→ 填地址 → 点「测试」→ 开始录制

### 关键实现细节

1. **直接输出 16kHz 单声道 PCM**
   ASR 只需要 16k，省一半磁盘，也省掉后续重采样。
2. **`-vn` 丢弃视频轨**
   CPU 占用几乎为零，录 8 小时也不吃力。
3. **断流自动重连**
   ```
   -reconnect 1 -reconnect_streamed 1 -reconnect_delay_max 10 -rw_timeout 30000000
   ```
   直播服务端关连接是常态（切片、负载均衡），不是故障。
4. **看门狗**
   90 秒没有新数据就判定断流；连续 3 次则停止并提示「地址可能已过期」。
5. **先探测再录**
   用 ffprobe 检查是否有音轨，避免录了几小时才发现没声音。

### 踩过的坑

- **chocolatey 的 ffmpeg 是大写 `.EXE`**
  `ff.replace("ffmpeg.exe", "ffprobe.exe")` 匹配不到，会把 ffmpeg 当 ffprobe 调用，
  报 `Error splitting the argument list: Option not found`。
  → 改用 `shutil.which("ffprobe")` + 同目录探测双保险。

- **重连会重发 13 字节 FLV 头**
  服务端重连时先发一遍 `FLV` 文件头，不丢弃会导致时间戳错乱、音画不同步。
  ffmpeg 的 `-reconnect` 已内部处理；如果自己写拉流逻辑必须手动处理。

- **地址会过期**
  `txTime` 是十六进制过期时间戳，配套 `txSecret` 签名。
  过期后返回 403，只能重新抓。

## 五、还需要什么才能全自动

目前是「手动填地址」。要全自动还缺一步：**自动抓地址**。

可选方案（都需谨慎，涉及证书与权限）：

1. **半自动**：手动用 Chrome DevTools / Fiddler 抓一次地址，填进 GUI
2. **mitmproxy 集成**：把 wxchannels-downloader 的注入脚本搬进来，自动捕获
3. **保留现状**：声卡回环已经零配置可用，URL 直录作为「追求音质时的可选升级」

**我的建议是先不自动化抓包。** 理由是：微信改版频繁，抓包方案需要持续维护；
而声卡回环的准确性经过实测已经足够（2 倍速播放都能正确转写），
URL 直录的收益主要在「长时间无人值守」和「音质」两个场景。
如果你确实需要这两个场景，再上抓包不迟。
