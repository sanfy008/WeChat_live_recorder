## 当天关键发现

1. **公网入口存在三层鉴权断层**：虽然 `server.py` 原本支持 `WXLIVE_TOKEN`，但① 只拦写不拦读；② PC 端 `fetch.py`/`gui_fetch.py` 与 NAS Web 控制台 `_DASHBOARD_HTML` 均未透传 `X-WXLIVE-Token`；③ `WXLIVE_ALLOWED_HOSTS` 环境变量此前未实现，域名访问全靠反代改写 `Host`。
2. **只读鉴权默认策略需贴合使用习惯**：公网开启 `WXLIVE_READ_AUTH=true` 后，网页每次新浏览器访问会强制弹窗索要 Token；用户明确反馈打开网页还要输密码过于繁琐，最终确定采用 **“网页免密只读（`WXLIVE_READ_AUTH=false`）+ 写操作与手机直推强制 `WXLIVE_TOKEN` + `WXLIVE_ALLOWED_HOSTS`”** 的折中安全边界。
3. **测试必须进入目标仓库根目录执行**：在工作树 CWD 下以绝对路径参数对另一目录的 `tests/` 运行 `pytest` 会导入旧工作树的 `wxlive` 包，导致 `ModuleNotFoundError: No module named 'wxlive.artifacts'`；进入正式目录执行后实测 **570 passed in 96.92s**。

## 异常与根因

- **异常 1**：昨晚长直播任务 `20261126_200453_2cea98`（9563.4s / 2055 句）录制与转写正常（`transcript_complete: true`），但产物状态停在 `llm_status: "partial: 第5部分摘要失败: The read operation timed out"`。
  - **根因**：`wxlive/postprocess.py::build_digest()` 在长文本分块摘要循环中直接调用 `_complete_multi(..., timeout=240)` 且无退避重试，网关单次 `read timeout` 即把失败占位符写入终稿。
  - **证据路径**：`wxlive/postprocess.py#L309-L360`、`tests/test_postprocess_truncation.py`
  - **下一步建议**：观察下一场 2 小时以上长直播的 `llm_status`，确认分块重试恢复日志与完整终稿表现。

- **异常 2**：今早任务 `20261127_080703_167a58` 在用户视觉上直播已停播后仍持续录制超 3 小时未停止。
  - **根因**：并非 NAS 静音判停失效（末尾 30s 实测 RMS `0.017 ~ 0.096` 远高于阈值 `0.002`），而是该任务推送于手机端修复“预加载串台”之前，标题抓成《小林升学答疑解惑，20261127》但实际流对应另一场仍在直播的英语课（《滚雪球造句法》）。
  - **证据路径**：NAS 现网任务 `20261127_080703_167a58` 分段音频抽样转写记录；手机端交接整改清单（`mwydufv3x1tl5szh1uu`）
  - **下一步建议**：待用户真机在手机端连续滑切 3 个直播间后点「NAS 解析」，验证标题与流地址无串台且带 Token 推送成功。

- **异常 3**：初配公网鉴权启用 `WXLIVE_READ_AUTH=true` 后，用户打开网页即被弹窗要求输入 Token，引起困惑。
  - **根因**：`server.py` 检测到 `readAuthRequired` 且浏览器 `localStorage` 无 Token 时触发门禁弹窗；虽然保护了公网隐私，但与用户“浏览免密、仅锁写入”的日常预期冲突。
  - **证据路径**：`wxlive/server.py#L1224-L1228`、`wxlive/server.py#L1927-L1948`、NAS `.env` 配置变更实测记录
  - **下一步建议**：维持 `WXLIVE_READ_AUTH=false`，若后续公网暴露面扩大再评估启用只读鉴权或反代层 Basic Auth。
