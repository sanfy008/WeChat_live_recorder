## 三个必须记住的教训

### 1. 我把「噪声」当成了「差异」，又把「差异」当成了「优势」

第一版结论是「`high` 与 `low` 无法区分」。这个结论**碰巧是对的**，但推理过程有一步是错的：
我先算了跨档位相似度（0.9933），再算 A/A 基线（0.9908），发现前者更高就下了结论。

**问题**：相似度高 ≠ 更接近正确答案。相似度只回答「两份输出像不像」，
不回答「哪份更对」。真正的问题是 `low` 和 `high` 各自改对了多少处 —— 这个我没测，
只做了抽样人工判读（21/80 行差异，各有改对改错）。

**可迁移的规则**：做「A 和 B 谁更好」的判断时，相似度只能用来**排除差异**
（差异在噪声内 → 没有可测差别），**不能用来排序优劣**。
要说 A 比 B 好，必须有一个「对不对」的外部判据，而不是「像不像」。

### 2. 度量本身会骗人，而且骗得很像真的

本轮连续踩了两次同类陷阱，都是「计数器算错了，结论就反了」：

| 陷阱 | 表现 | 真相 |
|---|---|---|
| 格式数字混进事实判据 | 算出 `low` 100% vs `high` 97.8% 的数字保真度 | 把列表序号 `9.` `12.` `13.` 当成事实数字。剔除行首序号后三档持平（99.4–100%） |
| 字数统计用错正则 | 算出「建议条数 0 / 存疑条数 0」，判为内容缺失 | `low` 用 `- ` 列表、`none` 用 `1.` 编号，正则只匹配了一种。改用兼容两种格式后 5 章节全完整 |
| A/A 基线跨语段计算 | 基线相似度算出 **0.03** | 把 s0/s1/s2 三个不同语段混在一起比。按语段分组后是 **0.9908** |

**可迁移的规则**：**度量写完后，先拿已知答案的样本验一次。**
上表第三条是在 `scripts/bench_effort.py` 里真实发生的 —— 脚本已经跑通了、
数字也打印了，但那个 0.03 明显不合理（两份都是同一份转写的纠错结果，
不可能只有 3% 相似）。**看到「明显不合理的数字」时，先怀疑度量，不要先相信它。**

### 3. 我上一轮给的优化建议，例子是错的

上一轮我说「扩领域词表更有效」，举的例子是「天河岗顶」「修业班」这类**地名/机构名**。

实测推翻：13804 句里有 1517 句被 LLM 改过，其中**只有 18% 含词表词**，
82% 的纠错与词表无关。高频错误是**直播内容词**：

```
他→它(79)  利益→立意(42)  韩→寒(35)  生→升(15)
含价/韩价→寒假(13)  解→截(12)  充→冲(12)
```

**方向没错，例子完全举错了。** 该扩的是「立意/寒假/升初/截取/冲刺」这类术语。

**可迁移的规则**：提优化建议时，**先统计一遍再举例**。
凭印象举的例子会指向错误的方向，而对方很可能按这个方向去投入。
