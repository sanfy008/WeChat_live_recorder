# ASR 方案对比实测报告

测试时间：2026-11-16 · 测试音频：微信真实直播录音（广州中考升学规划类）
环境：Windows / CPU only（无 NVIDIA GPU）/ magpie 本地网关 `127.0.0.1:3425`

---

## 一、先回答两个前提问题

### Q1: whisper small 性能是不是太差？

**是，有明显短板，但不至于不可用。** 实测同一段音频：

| 错误 | whisper small | 正确 |
|---|---|---|
| 它行驾会有一个**东丽银** | ❌ | 他**寒假**会有一个**冬令营** |
| **云城培营**考处中内容 | ❌ | **云城培英**考初中内容 |
| **明半**学校 | ❌ | **民办**学校 |
| **公半**的话 | ❌ | **公办**的话 |
| **省市用品**有付费MK | ❌ | **省实**（校名）有付费MK |
| **抗礼**在学校 | ❌ | **靠前**的学校 |
| 730**家** / 670**家** | ❌ | 730**+** / 670**+** |
| 再去**胖道** | ❌ | 再去**判断** |

错在**同音字**和**专有名词**上，语义能看懂但人名/校名/术语全错。对"随便看看讲什么"够用；
对"要归档、要检索、要引用"不够用。

### Q2: 能不能用 DeepSeek 这种大模型？

**不能直接用来听音频。** 实测三条证据：

1. 向 `group/deepseek` 发 `input_audio` → 回复："抱歉，我无法接收或处理你提到的这段音频附件"
2. 向 `workbuddy/deepseek-v4.1-flash` 发同样的音频 → 回复："音频未成功上传，无法转写"
3. DeepSeek 官方另有**独立 ASR API**（2026-11-13 发布），是语音识别专用服务，
   不是聊天模型的能力。它有硬限制：**单次 ≤120 秒、≤8 MiB、不支持流式**。
   价格：$0.116/小时（限时半价 $0.058），比本地跑贵，但极便宜。

DeepSeek 能接收的是**图片**（vision），不是音频。这是两个不同的模态。

## 二、实测：四个方案同台对比

同一段 120 秒真实直播音频，同一条 prompt。

| 方案 | 耗时 | RTF | 能听音频 | 中文准确度 | 备注 |
|---|---|---|---|---|---|
| **gemini-4-hydrogen** | 8.0s | **0.07** | ✅ | 高 | 最快，但会漏字 |
| **gemini-3.8-flash** | 9.2s | 0.08 | ✅ | 高 | **输出了繁体**，需后处理 |
| **gemini-4-argon** | 16.7s | 0.14 | ✅ | **最准** | 校名/口语最贴近原意 |
| deepseek-v4.1-flash | 2.7s | 0.02 | ❌ | — | 假速度：它根本没听，直接回复"无法转写" |
| faster-whisper small | 24.4s | 0.41 | ✅ | 中 | 本地，同音字错多 |
| faster-whisper medium | 104.7s | 1.75 | ✅ | 中+ | 慢 4 倍，只比 small 好一点，**性价比差** |

### 质量细节（关键差异点）

| 原文/原意 | whisper small | argon | hydrogen | 3.8-flash |
|---|---|---|---|---|
| 寒假冬令营 | 它行驾东丽银 ❌ | ✅ 寒假冬令营 | ✅ 寒假冬令营 | ✅ 寒假冬令營 |
| 六上没拿到**票** | 没拿到 ❌ | ✅ 拿到票 | ❌ 没拿他花 | ✅ 拿到票 |
| 省实（校名） | 省市用品 ❌ | 省实**幼平** ⚠️ | 陈氏用品 ❌ | ✅ 省**實**用品 |
| 730+ | 730**家** ❌ | ✅ 730+ | 730加 ⚠️ | 730家 ❌ |
| 再去判断 | **胖道** ❌ | ✅ 判断 | ✅ 判断 | ✅ 判斷 |
| 指标名额靠前 | 抗礼 ❌ | ✅ 靠前面 | ✅ 靠前 | ✅ 靠前 |

**结论：三个 Gemini 都明显强于 whisper，argon 综合最稳，hydrogen 最快，3.8-flash 会串到繁体。**

## 三、Gemini 路线的真实风险（必须知道）

1. **内容安全过滤会拦截**
   180 秒完整音频请求返回：
   `gemini-4-argon refused this request (safety filter: content_filter)`
   120 秒正常。也就是说长音频、或某些内容会被云端拒掉。
   → **必须有本地兜底**，不能把云端当唯一通道。

2. **单次 120 秒限制**
   实测 120s 稳定通过。直播动辄几小时，必须自己切片串行调用。

3. **会串到繁体**
   3.8-flash 输出整段繁体。需要用 prompt 约束 + 后处理（opencc）转简体。

4. **依赖公网 + 账号额度**
   走 magpie 网关，受上游账号状态影响（实测 group/deepseek 就撞到
   `WorkBuddy restricted this account`）。

5. **隐私**
   直播音频会上传到 Google Vertex。如果是内部会议、私密内容，这条不能走。

## 四、DeepSeek 的真正价值：ASR 后纠错

不能听音频，但能在 ASR 之后做同音字修正。实测 `workbuddy/deepseek-v4.1-flash`：

| 错误 | 修正 |
|---|---|
| 它行驾会有一个东丽银 | → **它寒假会有一个冬令营** ✅ |
| 云城培营考处中内容会小建议 | → **云城培英考初中内容会少，建议** ✅ |
| 省市用品有付费MK | → **省实培英有付费MK** ✅ |
| 抗礼在学校 | → **靠前的学校** ✅ |
| 730家 | → **730+** ✅ |
| 明半/公半 | → **民办/公办** ✅ |

**修对了 6 类关键错误。** 但注意：
- 每行耗时约 1.5s（含思考），一段 120s 直播约 30 行 → 45s 后处理
- 它也会**脑补**（把"省市用品"改成"省实培英"，多出一个词）
- 必须给它领域词表，否则效果差

### 成本对比（120 秒音频 / 约 30 行）

| 方案 | 单次成本 |
|---|---|
| imported/DeepSeek-V4-Flash 纠错 | ≈ $0.000065 |
| imported/DeepSeek-V4-Pro 纠错 | ≈ $0.00013 |
| Gemini 转写（按 Vertex 音频计费） | ≈ $0.001-0.002 |

纠错成本比转写低一到两个数量级，是性价比极高的一步。

## 五、推荐架构

```
录音（WASAPI loopback，已实现）
    │
    ├─► 本地 faster-whisper small   ← 兜底通道，永远可用、隐私安全
    │       │
    └─► 云端 Gemini argon/hydrogen ← 质量通道，需切 120s 片
            │
            ▼
    文本合并 + 繁转简（opencc）
            │
            ▼
    DeepSeek-V4-Flash 同音字纠错（带领域词表）
            │
            ▼
    结构化输出 → LLM 分析
```

**策略建议：双通道 + 自动降级**

1. 默认走 **本地 whisper small**：不依赖网络、不花钱、不泄露隐私、不会因 120s 限制断流
2. 需要高质量时，对已保存的 WAV 做 **Gemini 重转**（事后批量，不占用录制链路）
3. 最后可选 **DeepSeek 纠错**（给它这场直播的领域词表，效果最好）
4. 云端失败（content_filter / 额度 / 网络）→ 自动回退本地，不阻塞

**为什么不是"直接上 Gemini 实时"**
- 120s 限制 + 内容过滤 → 长直播必然中途断，且无法预测哪段被拦
- 录音链路必须绝对可靠，云端不确定性不能放进主链路
- 先录后转的成本几乎为零（CPU 空闲时跑），质量还能用最好的模型

## 六、结论

| 你的问题 | 答案 |
|---|---|
| whisper small 是不是太差？ | 同音字/专有名词确实差，但作为兜底够用；追求质量用 Gemini |
| 错漏会多吗？ | whisper small 关键名词错误率高；Gemini 显著更低 |
| 有更好的模型吗？ | 有：gemini-4-argon（最准）/ hydrogen（最快），实测碾压 whisper |
| 能用 deepseek 吗？ | **不能听音频**。但它是极好的 ASR 后纠错工具，成本低到可忽略 |
