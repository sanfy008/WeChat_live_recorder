# 转录产物定期复盘：可行，但要换个做法（2026-11-26）

> 起因：上一轮我建议"扩领域词表更有效"，举的例子是「天河岗顶」「修业班」。
> King 追问「这项任务是否可以定期复盘更新」。
>
> 我拿最近几天全部 7 份真实产物做了复盘实验（13804 句 / 25.2 万字）。
> **结论：可以定期复盘，而且值得做 —— 但我上一轮那句建议的前提是错的。**

---

## 一、先纠正我上一轮的错误前提

我上一轮说「扩词表比提档位有效」，隐含假设是：**纠错的主要难点在校名/机构名**。

实测推翻了这个假设：

| 指标 | 实测值 |
|---|---|
| 被 LLM 改过的句子 | **1517 / 13804 = 11.0%** |
| 其中含词表词的（校名/术语/暗语） | **279 / 1517 = 18%** |
| → 词表覆盖不到的 | **82%** |

**82% 的纠错与词表无关。** 高频错误长这样：

| 频次 | 错误 → 正确 | 类别 |
|---|---|---|
| 79x | 他 → 它 | 代词（机器听觉混淆） |
| 42x | 利益 → 立意 | 领域同音词 |
| 35x | 韩 → 寒 | 领域同音词（寒假） |
| 23x | 的 → 得 | 助词 |
| 15x | 生 → 升 | 领域同音词（升初） |
| 13x | 含价 / 韩价 → 寒假 | 领域同音词 |
| 12x | 解 → 截 | 领域同音词（截取） |
| 12x | 充 → 冲 | 领域同音词（冲刺） |

这些是**直播内容词**（立意、寒假、升初、截取、冲刺），不是校名。
`schools`（170 条）和 `codes`（264 条）都覆盖不到它们。

**所以"扩词表"这个方向本身没错，错的是我举的例子 —— 该扩的是领域术语，不是地名。**

---

## 二、复盘真正挖出的问题，比词表重要得多

做完六项体检，发现两个**确定性缺陷**，都不是"词表不够全"：

### 2.1 有一场 ASR 路径漏了繁简转换（574 句）

| 场次 | ASR 路径 | 终稿繁体句 | 可修未修 |
|---|---|---|---|
| 20261117_122741 | ? | 0 | 0 |
| 20261117_213458 | ? | 0 | 0 |
| 20261119_003234 | ? | 0 | 0 |
| 20261119_004936 | ? | 0 | 0 |
| 20261119_223040 | ? | 0 | 0 |
| **20261120_190932** | **Gemini** | **574** | **574** |
| 20261120_222439 | sensevoice | 0 | 0 |

只有那一场有问题。它的 `meta.asr` 长这样（没有 `backend` 字段，RTF 0.47）：

```json
{"audio_seconds": 7646.0, "infer_seconds": 3576.1, "rtf": 0.47}
```

而正常那场是：

```json
{"backend": "sensevoice", "model": "csukuangfj/sherpa-onnx-sense-voice-...",
 "num_threads": 2, "audio_seconds": 6196.3, "infer_seconds": 625.4, "rtf": 0.1}
```

`gemini_asr.stats` 的结构正好是前者（无 `backend`，有 `bad_detected` 等质量字段）。

**判据：终稿里有繁字体，且 `to_simplified()` 本可以修掉 → 说明该场走了没调
繁简转换的路径。** 这是确定性缺陷，不是模型波动，靠复盘能一眼抓到。

### 2.2 两场 Gemini 幻觉句子进了终稿

```
20261117_122741 [1047] 未检测到音频附件（仅收到 [attachment audio/wav] 文本占位符），无法进行音频转写。请重新上传……
20261119_004936 [114]  无法完成转写。当前会话中未包含可读取的音频文件（仅出现文本标记 [attachment audio/wav]）……
```

**这两句读起来像正常正文，还被 LLM 纠错顺手改通顺了。** 按原有验收（行数守恒、
失败批 0、三份产物齐全）**完全查不出来**。

这正是项目里反复出现的「产物看起来正常比报错更危险」。复盘加一条正则就能扫到。

## 三、"定期"该怎么做：只读产物，不重跑

关键可行性判断：**复盘不需要重跑 ASR，也不需要调 LLM。**

复盘的原料是 `raw_text`（LLM 改之前的原文）和 `text`（改之后）。
两者都已在产物里。所以复盘是纯读 JSON，**秒级完成、零 API 成本、不影响正在录制的直播**。

这一点很重要 —— 如果复盘要重跑一遍 ASR，那单场就要 10-60 分钟（实测
`infer_seconds` 从 625s 到 3576s 不等），根本不可能定期做。

### 已固化成脚本

```bash
python scripts/lexicon_retro.py                # 最近 7 天
python scripts/lexicon_retro.py --days 30      # 最近 30 天
python scripts/lexicon_retro.py --all          # 全部
python scripts/lexicon_retro.py --json r.json  # 机器可读，便于做趋势
```

六项体检：

| # | 检查项 | 性质 | 实测基线（全量） |
|---|---|---|---|
| 1 | 繁简残留 | **确定性缺陷**，应清零 | 574 句 |
| 2 | ASR 幻觉残留 | **确定性缺陷**，应清零 | 2 句 |
| 3 | 词表贡献度 | 指标，判断扩词表收益 | 18% |
| 4 | 高频替换候选 | 供人工筛选 | top 20 |
| 5 | 数字化规范候选 | B 级提示 | 184 句 |
| 6 | 数据可用性 | 防止把缺字段当错误 | 12287/13804 句无 raw_text |

第 6 项是必须有的护栏：7 份产物里有 5 份是早期产物，`raw_text` 字段整体缺失。
**如果把"raw_text 为空"当成"该句无纠错"，会得出"纠错率只有 12%"的错误结论** ——
实际能参与复盘的只有 1517 句。

## 四、频率建议

| 频率 | 做什么 | 理由 |
|---|---|---|
| **每场录制后**（自动） | 只跑第 1、2 项 | 这两项是缺陷，一旦出现当次就该知道，不该等到周末 |
| **每周** | 全量六项 + 看趋势 | 7 份产物跑完 < 2 秒，周频足够 |
| **每月** | 人工筛第 4 项候选 → 决定入不入词表 | 入库有误伤风险，必须人工 |

**不建议做成"每场自动改词表"。** 原因见下节。

---

## 五、为什么候选不能自动入库（这条要守住）

`lexicon.correct_text()` 是**全局子串替换**（长词优先，但仍是子串）。

实测风险：

| 候选 | 在语料里出现次数 | 自动入库后果 |
|---|---|---|
| 他 → 它 | **1386 次** | 绝大多数「他」是正确的，会大面积改成「它」 |
| 平 → 屏 | 302 次 | 「平行」「平均」全废 |
| 出 → 初 | 436 次 | 「出来」「出口」全废 |
| 派 → π | 139 次 | 「派位」「派系」会被改成「π位」 |

**所以第 4 项只做候选清单，入不入由人判断。** 该入的是「长词」：
`利益→立意`、`含价→寒假`、`韩价→寒假` 这类 2 字以上、且只在该领域成立的。

有一个反例要注意：`境界→进阶` 只在升学语境成立，但「境界」在中文里
是正常词（"思想境界"）。语料里只出现 3 次，没法判断长期安全性 —— 这类应该
先放 `_待确认`，而不是直接进 `corrections`。这正是词表现有 `_待确认` 字段的用途。

---

## 六、结论

| 问题 | 答案 |
|---|---|
| 能不能定期复盘？ | **能，而且成本几乎为零**（只读 JSON，不重跑 ASR/LLM） |
| 值得做吗？ | **值得** —— 这次实测就抓出 574 句繁简残留 + 2 句幻觉残留，都是现有验收漏掉的 |
| 频率？ | 每场跑缺陷项（< 1 秒）；每周全量；每月人工筛候选 |
| 产出能自动写进词表吗？ | **不能。** 单字替换会大面积误伤，必须人工确认 |
| 我上一轮的建议对吗？ | **方向对，例子错。** 该扩的是「立意/寒假/升初/截取/冲刺」这类直播术语，不是地名 |
